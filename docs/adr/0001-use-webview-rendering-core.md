# ADR 0001：采用 WebView 渲染核心

## 状态

已接受

## 背景

第一版目标平台是 macOS 与 iOS，同时需要为 Windows 桌面预留架构空间。产品第一版同时支持 GP 与 MIDI，并且需要较强的练习交互。

研究报告显示，alphaTab 是 GP 渲染与播放方向最贴近需求的开源底座。alphaTab、piano-roll、基础钢琴谱、播放跟随和练习交互都天然适合在 Web 技术栈中快速迭代。

## 决策

采用“WebView 渲染核心 + 原生壳 + 平台桥接”的架构。

Web Viewer Core 负责：

- GP 渲染与播放跟随。
- MIDI piano-roll。
- 基础钢琴谱。
- 播放时间轴。
- 练习交互。
- sidecar 应用。

macOS 与 iOS 原生壳负责：

- 文件访问。
- 应用导航。
- 系统权限。
- 本地存储。
- 同步入口。
- 后续原生音频桥。

## 后果

正面影响：

- 最大化复用 GP 与 MIDI 的渲染交互代码。
- 后续支持 Windows 时可以复用核心。
- alphaTab 集成路径更短。
- 第一版更容易快速验证产品价值。

负面影响：

- WebView 与原生桥接会成为关键复杂点。
- 原生质感需要额外打磨。
- 后台播放、低延迟音频、外设能力需要平台桥接补齐。

## 约束

- Bridge API 必须版本化。
- Web Viewer Core 不能直接依赖某个平台的私有能力。
- Native Shell 不能拥有乐谱排版与播放时间轴的核心逻辑。
