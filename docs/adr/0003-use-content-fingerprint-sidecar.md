# ADR 0003：sidecar 绑定内容指纹

## 状态

已接受

## 背景

第一版采用本地文件优先和轻量同步。用户可能在 macOS 与 iOS 上通过不同路径访问同一份谱，例如本地下载、iCloud Drive、AirDrop 或文件 App。

如果 sidecar 绑定路径，跨设备和文件移动会频繁失效。如果要求导入自有曲库并生成内部 Score ID，第一版会过早承担完整曲库管理复杂度。

## 决策

sidecar 绑定 `ScoreIdentity`。`ScoreIdentity` 以内容指纹为主，以格式内元信息为辅助。

身份来源：

- 文件内容 hash。
- 标题、艺术家、轨道名、时长、拍号、tempo map 等元信息。
- 文件路径仅作为最近访问和重定位线索。

## 后果

正面影响：

- 同一份谱在不同设备和路径下仍能匹配到同一份练习元数据。
- 不需要第一版建立完整自有曲库。
- 与轻量同步策略一致。

负面影响：

- 大文件 hash 需要考虑性能。
- 文件轻微修改后可能被视为不同谱。
- 元信息相似匹配需要谨慎，避免误关联。

## 实现约束

- sidecar schema 必须版本化。
- 自动匹配失败时，可以提示用户手动关联。
- 不上传原始谱文件作为匹配前提。
