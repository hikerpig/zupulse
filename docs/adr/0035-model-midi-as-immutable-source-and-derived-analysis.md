# ADR 0035：将 MIDI 建模为不可变源数据与派生分析

## 状态

已接受

## 背景

MIDI 文件记录的是演奏事件，而不是已经排版完成的乐谱。量化、拍号推断、左右手分配和基础钢琴谱生成都带有推断性质，并且可能因为参数、算法版本或用户修正而变化。

如果导入过程直接把推断结果写回唯一模型，系统将难以可靠地重新量化、升级分析算法、撤销错误处理，piano-roll 也无法保证忠实呈现源文件。

## 决策

MIDI 导入与处理采用三层模型：

1. `Raw MIDI`：由文件解析得到的不可变源事件，是 MIDI 内容的事实源。
2. `Analysis Revision`：从指定 Raw MIDI、分析参数和算法版本派生的可重算结果。
3. `User Corrections`：用户对分析结果施加的修正或覆盖，不改写 Raw MIDI。

量化、拍号推断、左右手分配、异常检测和基础钢琴谱均属于分析结果。piano-roll 默认以 Raw MIDI 为依据；需要便于练习的吸附或分手显示时，可以显式叠加分析结果。

## 后果

正面影响：

- 用户可以改变参数并安全重算。
- 分析算法升级后可以生成新 revision，而不破坏源数据。
- 用户可以撤销修正或回到原始演奏事件。
- piano-roll 与基础钢琴谱分别承担“忠实表达”和“可读推断”的职责。

负面影响：

- 数据模型和持久化必须表达层次、来源与版本关系。
- 用户修正需要定义在重算后的迁移或失效规则。
- 同一 MIDI 可能同时存在多个分析 revision。

## 约束

- Raw MIDI 一经导入不得被分析或编辑流程原地修改。
- 每个 Analysis Revision 必须记录输入内容身份、算法版本和分析参数。
- User Corrections 必须能追溯到其目标 revision 或稳定的原始音乐位置。
- 原始 MIDI 文件仍保持只读；练习数据和修正写入 sidecar 或本地存储。
