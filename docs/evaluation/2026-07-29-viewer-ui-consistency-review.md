# Viewer UI 一致性评审

- 评审日期：2026-07-29
- 评审对象：Browser Viewer（含 Library 入口页）
- 评审方式：以 UI 设计师视角实际操作 demo（`http://localhost:5173/`），深色/浅色主题、
  1280×800 与 390×844 两种视口，并用 computed style 对控件尺寸、颜色、字号做了量化采样
- 评审范围：视觉一致性（按钮样式、颜色、尺寸、圆角、字号）与基础交互可用性。
  功能正确性、音频体验不在本次范围内

## 结论概述

Viewer 的整体信息架构和播放体验是成立的，但控件层缺乏一套统一的组件规范：同一工具栏内
按钮有 5 种高度、3 种圆角、3 种背景灰、2 种字号；主色 coral 存在两个不同色号，且同时
承担 primary action、active state、link-button 三种语义。进度条（seek）是目前可用性最差
的控件：轨道仅 2px 高、拖拽手柄 8×8px，几乎不可见也无法精确拖动。

## 问题清单

### P0 进度条几乎不可操作

- 轨道高度仅 2px，thumb（`aria-label="播放进度"` 的 input）实际渲染为 8×8px，视觉上
  只是一个小灰点，用户很难发现可以拖动，更难精确点击。
- 轨道为全宽布局（x=0, w=1280），位于播放栏底部边缘，播放时 coral 填充线从左侧按钮簇
  下方穿过，与按钮区域在视觉上互相干扰。
- `transportDivider`（x≈609 的 1px 竖线）孤立在左右控件簇之间的空白区域中央，看起来像
  残留元素，没有分隔任何内容。

### P1 播放控制栏按钮规格混乱（用户主诉，已量化证实）

同一 `transportBar` 内 6 个控件的实测值：

| 控件         | 尺寸   | 圆角           | 背景          | 字号 |
| ------------ | ------ | -------------- | ------------- | ---- |
| 播放         | 40×44  | 6px            | coral 实心    | 16px |
| 停止         | 36×36  | 9999px（圆形） | rgb(56,56,55) | 12px |
| 循环模式     | 36×36  | 9999px（圆形） | transparent   | 12px |
| 谱面导航模式 | 42×37  | 6px            | rgb(39,39,39) | 16px |
| 速度 120 BPM | 125×34 | 10px           | rgb(56,56,55) | 16px |
| 练习设置     | 113×38 | 6px            | rgb(39,39,39) | 16px |

即：5 种高度（34/36/37/38/44）、3 种圆角、3 种背景、2 种字号，全部挤在同一行。图标按钮
的形状语言也分裂：播放是圆角矩形，停止/循环却是正圆形，三者并排时显得不属于同一套组件。

### P1 主色不统一且语义过载

- coral 存在两个色号：播放按钮 `rgb(245,130,106)`，Library「导入曲谱」按钮
  `rgb(242,107,79)`，肉眼可见地一个偏浅一个偏深。
- 同一 coral 同时表达三种语义：primary action（导入曲谱、播放）、active/on 状态（收起设置、
  全宽模式、浅色主题按钮、弹层触发按钮的激活态）、link 型按钮（和弦分析）。用户无法从
  颜色判断「点它会执行动作」还是「它正处于开启状态」。
- Library 的成功提示条与 MUSICXML 徽章引入了一套绿色 accent，全站仅此两处，与 coral
  体系没有任何关联，像来自另一个产品。

### P2 弹层（popover）之间样式不一致

- BPM 弹层的选项是纯文本行列表；「谱面导航模式」弹层的选项是带边框的盒式卡片行。两个
  弹层从同一工具栏弹出，菜单项却是两种视觉语言。
- BPM 弹层使用原生 number input，带有浏览器默认的上下 spin 按钮，与其余自定义控件
  风格冲突。
- BPM 弹层弹出位置覆盖在谱面之上，遮挡了正在查看的内容；练习设置走右侧 drawer，BPM 走
  浮动 popover，导航模式又是居中小菜单，三种设置入口三种容器形态。

### P2 曲谱库筛选行控件不齐

- 同一行三个控件三种字号：搜索框 16px、「收藏」按钮 13px、排序 select 12px。
- 「排序」是裸文本标签直接贴着原生 select，而「收藏」是带边框的 toggle 按钮，标签与
  控件的对齐关系不统一。
- 排序使用原生 `<select>` 下拉，外观由浏览器主题决定，与全站自定义控件不一致。
- 统计文案「1 份曲谱 · 0 个 Loop」中英混排，「Loop」未本地化。
- 曲谱卡片右侧三个操作图标（打开/收藏/更多）在浅色主题下对比度极低，接近不可见。

### P2 页头与层级

- header 的「语言」「深色/浅色」按钮为 36px 高、12px 字号，与页面主按钮（44px、16px）
  差异过大；二者同处一行时层级关系含糊。
- 浅色主题下「浅色」按钮呈 coral 描边（active 态），旁边的「语言」是灰底，两个并列按钮
  看起来像一个有状态一个没有，但「语言」其实也有当前值（中文）。

### P3 窄屏（390×844）

- 底部播放栏的 BPM 徽标整个消失，窄屏下看不到当前速度，调速只能进练习设置 drawer，
  路径明显变深。
- 右下角「谱面导航」「练习设置」图标按钮紧贴视口右缘，疑似被裁切。
- 其余折叠策略（logo 收成图标、和弦分析收成图标按钮、谱面转纵向排版）是合理的。

### P3 其他观察

- 播放中暂停图标在 44px coral 按钮内视觉比重明显小于播放三角，两个状态不像同一图标的
  切换（待设计稿确认）。
- 导入流程曾出现一次卡死在「已处理 0 / 1」且无错误提示的情况，刷新后重试成功。这属于
  功能 bug，但 UI 层面至少应暴露失败原因，而不是无限停留在进行中状态。

## 修复方向建议（供后续排期参考）

1. 先定义一套控件 token：高度（建议 32/36/44 三档）、圆角（6px 统一，圆形仅限纯图标
   toggle）、字号（工具栏统一一档）、三种按钮变体（primary / secondary / icon-ghost），
   然后把 `transportBar`、曲谱库筛选行、header 全部对齐到 token。
2. 主色收敛为一个 coral 色号，并把 active 状态从「主色填充」改为可区分的表达（如描边 +
   底色微亮），释放 coral 的语义。
3. 进度条加高轨道（hover 时至少 6px）、放大 thumb（≥14px），并移除孤立的
   `transportDivider`。
4. 统一弹层容器与菜单项样式；BPM 输入框替换掉原生 spin 按钮；设置类入口统一为 popover
   或 drawer 其中一种。
5. 绿色 accent 并入主色板或替换为中性色 + 图标表达。
