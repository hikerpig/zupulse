# Viewer 工作台表面重构设计

## 目标

将当前 viewer 从偏网页化的 panel 拼接界面，重构为更紧凑、更像音乐产品工作台的练习界面。新的界面需要减少无意义的 panel 间距，提升有效内容密度，并引入非常克制的高细腻度哑光金属质感，让页面更接近专业音乐软件或练习设备，而不是通用 web demo。

本次设计沿用现有信息架构与交互能力，不新增业务范围。重点只放在视觉结构、边界系统、表面材质和明暗主题表现。

## 现状问题

- `.workspace` 外围留白偏大，主工作区更像网页内容区域而不是练习工作台。
- `.score-stage` 与 `.practice-panel` 之间主要依赖较大的视觉间隔进行分区，导致整体被切碎。
- 右侧 `Loop / Tracks / Session` 区域更像通用设置抽屉，而不像音乐产品中的控制仓。
- 顶部 `transport-bar` 偏平，控件分组关系弱，缺少主控制排的产品辨识度。
- 当前表面质感主要依赖纯色、圆角和阴影，容易出现“AI 生成网页”式的组件拼装感。

## 设计方向

采用 `Continuous Surface + Soft Metal Overlay`。

- `Continuous Surface`：viewer 的主工作区不再由多个强卡片组成，而是读作同一张连续工作台中的不同分仓。
- `Soft Metal Overlay`：只在顶部控制带和右侧控制壳层加入极轻微的哑光金属质感，乐谱阅读面保持干净。

该方向的优先级是：

1. 先解决结构松散和间距冗余。
2. 再通过轻度材质提升产品感。
3. 最后确保乐谱区始终是视觉中心。

## 布局结构

整体结构继续保持顶部上下文区、顶部播放控制区和中部工作区三层，不新增营销式头图、底部信息区或额外浮层。

### 页面骨架

- `.context-bar` 保持为轻量信息眉栏，用于标题、文件状态、主题切换与打开文件动作。
- `.transport-bar` 作为主控制带，承担播放、停止、进度、速度、音频状态和练习设置入口。
- `.workspace` 作为主工作台，负责承载左侧乐谱区和右侧练习控制仓。

### 工作区布局

- `.workspace` 的外围 padding 需要明显收紧，目标是从“内容留白”转为“设备容差”。
- `score-stage` 与 `practice-panel` 继续双栏布局，但两栏之间不再依赖显著 gap，而是依赖细边界或极窄分仓缝隙。
- 右栏宽度保持稳定，建议维持在 `320px` 到 `344px` 的范围内，优先确保控制项密度和秩序。
- 在窄屏断点下，右侧控制仓仍然可以降为下方单列，但桌面端应明确保持工作台模式。

## 边界系统

新界面的边界规则从“卡片隔离”切换为“壳体分仓”。

### 层级

- 外层：viewer 连续工作台壳层。
- 中层：乐谱区与控制区的主分仓。
- 内层：section、控件与列表项的功能容器。

### 具体规则

- `.workspace` 读作一整块连续表面，不再让左右区域分别呈现为两张悬浮卡片。
- `.score-stage-frame` 改为薄边界、轻内凹和弱阴影，避免厚重悬浮感。
- `.practice-panel` 贴合在右侧工作台之内，整体更像控制仓而不是 overlay drawer。
- `Loop / Tracks / Session` 三个 section 不再强调独立 card 感，而是统一归属于一个连续壳体中的三个分仓。
- section 之间主要用细分界线、浅底差和统一 header strip 表现层级。

设计上应减少高半径圆角与显眼阴影的数量，让视觉重点从“组件轮廓”回到“界面秩序”。

## 顶部主控制带

`transport-bar` 需要从通用 toolbar 提升为音乐产品的主控制排。

### 结构表现

- 整体高度更薄，横向连续性更强。
- 播放按钮、进度、速度和状态区域仍保持原有功能分组，但视觉上应被统一进同一条控制带。
- 分组之间使用细竖向 divider 或极轻的槽位变化，而不是多个独立小组件。

### 控件表现

- 播放和停止按钮保留高识别度，但边缘更精密，不要继续使用典型网页按钮观感。
- `speed-control` 从“单独表单块”调整为嵌入控制带中的参数槽。
- `status-chip` 更像设备状态指示件，不像普通 badge。
- 控制带背景加入非常轻的表面高光、弱渐变和几乎不可察觉的微噪点，形成哑光金属质感。

### 气质约束

- 需要专业、克制、精密。
- 不做概念图式的发光、未来感纹理或夸张金属反射。
- 不允许顶部控制带抢过乐谱区的视觉中心。

## 乐谱区

乐谱区是内容中心，必须保持纯净。

### 容器策略

- 可以改造 `score-stage-frame` 的外壳表现，但不对乐谱阅读面本身增加 texture。
- 乐谱外层 frame 改为更薄的结构边界，减少过厚 padding 和强悬浮感。
- 乐谱白底继续保持清晰、明亮和高可读性，作为 viewer 中最干净的一块区域。

### 视觉关系

- 乐谱区应表现为被精密嵌入工作台中的谱面窗口。
- 外层 frame 与内层乐谱之间可以保留一圈很轻的结构边界，用于建立“设备窗口”感。
- 光影重点放在边界存在感，而不是大面积投影。

### 禁止项

- 不在乐谱白底上叠加金属纹理、噪点或装饰背景。
- 不引入会干扰阅读的表面效果。
- 不让乐谱区回到厚卡片或内容容器式网页观感。

## 右侧练习控制仓

右侧 `practice-panel` 是本次提升“音乐产品感”的重点区域。

### 整体定位

- 它不应再像普通设置抽屉。
- 它应读作工作台右侧的控制仓，承担循环、轨道和会话状态等专业操作。

### 分仓规则

- `Loop / Tracks / Session` 共用一个连续壳层。
- 每个 section 使用统一 header strip，像设备中的模块铭牌。
- section 内部 spacing 要比当前更紧凑，减少 web 表单式松散感。

### 列表项与控件

- `loop row` 和 `track row` 从普通列表项转为更精密的控制行。
- slider 变得更细、更准，不使用厚重轨道。
- toggle、checkbox、数值输入框和音量控制需要弱化浏览器默认感，更接近参数控制件。
- “选择 / 删除 / 静音 / 独奏”等动作需要明确主次，不应让所有按钮权重一致。

### 视觉目标

- 右侧区整体更像专业工具面板。
- 信息密度提高，但不显脏、不显挤。
- 与顶部控制带形成同一产品语言。

## 材质策略

材质必须极度克制，只用于提升产品感，不能成为主视觉噱头。

### 允许使用的质感

- 极轻微表面渐变。
- 几乎不可察觉的细噪点。
- 很弱的边缘高光或内阴影。

### 建议出现的位置

- `.transport-bar`
- `.practice-panel` 外壳
- 少量 `.panel-header`

### 不建议出现的位置

- 乐谱白底
- 大块正文背景
- 列表项内容区
- 文本密集区域

### 质量标准

- 用户第一眼先感知结构和内容。
- 第二眼才感知表面更细腻。
- 不应让人一眼看出“这里刻意加了 texture”。

## 明暗主题策略

明暗主题需要共用同一套工作台逻辑，而不是简单反色。

### Light

- 主体基底采用偏暖灰白，接近工作台或设备外壳。
- 哑光金属感优先体现在浅暖灰表面上。
- 乐谱区域保持纯净暖白，避免脏灰。

### Dark

- 不使用纯黑，改用石墨灰、炭灰和微暖中性灰。
- 金属感通过更弱的高光和更细的边界体现。
- 避免赛博霓虹与概念稿式科技感。

### 共同要求

- 两个主题都应保持高密度、强秩序和轻材质。
- 两个主题都要读作成熟音乐产品，而不是视觉探索海报。

## 非目标

- 不新增功能区、复杂混音控件或新的业务流程。
- 不改变播放、速度、循环、轨道控制的核心交互逻辑。
- 不引入重拟物旋钮、夸张硬件复刻或渲染式金属效果。
- 不让 viewer 走向赛博、未来、发光 UI 风格。
- 不在乐谱阅读面加入任何会降低可读性的 texture。

## 成功标准

- 页面第一眼更像音乐产品工作台，而不是 AI 生成网页。
- 有效内容密度更高，panel 间无意义留白被显著压缩。
- 乐谱仍然是绝对视觉中心。
- 顶部控制带与右侧控制仓形成统一产品语言。
- 材质感存在但极其克制，不会盖过信息结构。
- Light 与 Dark 主题都保持专业、精密、耐看。

## 测试与验收

- 视觉回归应重点检查 `.workspace` 外围 padding、双栏分仓边界和右栏密度是否符合新规则。
- 在桌面视口确认 `.score-stage` 与 `.practice-panel` 读作同一工作台中的左右区域，而不是两张独立卡片。
- 检查 `transport-bar` 是否形成主控制排气质，而不是多个散装控件。
- 检查乐谱阅读面是否依旧干净，无纹理污染或可读性下降。
- 在 Light 与 Dark 主题下分别检查顶部控制带、右侧控制仓和 section header 的表面质感强度，确认质感轻到不会被优先注意。
- 在窄屏断点确认单列降级仍然清晰，不引入不必要的浮层感或复杂嵌套滚动。
