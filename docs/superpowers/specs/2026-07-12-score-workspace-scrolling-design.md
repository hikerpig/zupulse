# 谱面工作区内部滚动设计

## 目标

桌面端将 Tab Viewer 作为占满视口的练习工作台。顶部文件上下文栏和播放控制栏保持可见，谱面在自己的容器内滚动，右侧 Loop 与 Tracks 工具保持可用。alphaTab 播放跟随只操作谱面滚动容器，不再被顶部栏遮挡。

## 桌面布局

- `.app-shell` 高度使用 `100dvh`，网格行保持为上下文栏、播放控制栏和剩余工作区。
- 页面根节点不承担桌面端谱面滚动。
- `.workspace` 占满第三行并设置 `min-height: 0`，防止长谱面撑开视口。
- `.score-stage`、`.score-stage-frame` 和 `.score-viewer` 逐层传递可用高度。
- `.score-viewer` 使用 `overflow: auto`，成为唯一的谱面滚动容器。
- `.practice-panel` 保持在工作区右栏；当自身内容超过可用高度时独立滚动。

## alphaTab 播放跟随

初始化 alphaTab 时，将 `player.scrollElement` 指向当前实例的 `.score-viewer` 元素。alphaTab 的小节定位和播放自动跟随因此只更新谱面容器的 `scrollTop`，不滚动文档，也不需要通过固定像素偏移补偿顶部栏。

游标层与谱面层继续共享同一个 alphaTab 宿主节点。此前移除空状态节点的处理保持不变，避免再次引入坐标原点偏移。

## 响应式行为

桌面双栏布局采用视口工作台模式。在窄屏断点下：

- 工作区切换为单列。
- 应用恢复自然页面高度与页面滚动。
- 谱面取消桌面端视口高度约束，避免手机上出现狭窄的嵌套滚动区域。
- 右侧练习面板回到普通文档流，不使用固定或 sticky 定位。

## 状态与错误处理

- 空状态仍在尚未打开文件时显示；开始创建 alphaTab 会话前清空宿主节点。
- 文件加载失败沿用现有状态区错误信息，不引入新的覆盖层。
- 切换文件时沿用现有会话销毁和串行打开逻辑；新的 alphaTab 实例始终接收当前谱面容器作为滚动目标。

## 测试与验收

- 单元测试验证传给 alphaTab 的 `player.scrollElement` 是谱面宿主元素。
- CSS 回归测试验证桌面端视口高度、工作区收缩、谱面内部滚动及窄屏降级规则。
- 在桌面视口真实加载 GP 文件并播放，验证：
  - 文档滚动位置不随播放变化。
  - 谱面容器随当前小节滚动。
  - 当前小节和拍游标始终处于谱面可视区域，不被顶部栏遮挡。
  - Loop 与 Tracks 面板在谱面滚动期间保持可见。
- 在窄屏视口检查单列布局、键盘可达性和无不可操作的嵌套滚动区。

## 非目标

- 不重新设计顶部栏、播放控件、Loop 或 Tracks 的视觉样式。
- 不修改 alphaTab 游标颜色、播放控制器或持久化模型。
- 不为桌面端增加可拖拽分栏或用户可配置高度。
